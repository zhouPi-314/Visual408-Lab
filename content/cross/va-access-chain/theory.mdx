# 虚拟地址访问链路

一次普通访存，在硬件与操作系统之间要走完八步：

| # | 阶段 | 谁在做 | 失败会怎样 |
| --- | --- | --- | --- |
| 1 | 拆分地址 | MMU | — |
| 2 | 查 TLB | MMU | 未命中 → 查页表 |
| 3 | 查页表 | MMU | 页不在内存 → 缺页 |
| 4 | 缺页处理 | 操作系统 | 调页、更新页表与 TLB |
| 5 | 合成物理地址 | MMU | — |
| 6 | 查 Cache | CPU | 缺失 → 访问主存 |
| 7 | 访问主存 | 存储系统 | 装入 Cache 块 |
| 8 | 返回数据 | CPU | — |

## 最容易混的两个「命中」

- **TLB 命中**：虚拟页 → 物理页 的映射缓存命中，省掉页表访问。
- **Cache 命中**：物理地址对应的主存块已在 Cache 里，省掉主存访问。

二者**互不蕴含**。同一次访问可以 TLB 命中却 Cache 缺失（换了 offset → 换块），
也可以 Cache 命中却 TLB 缺失（虽然少见，但完全可能）。

## 缺页和 Cache 缺失的层级不同

- 缺页：动的是**页表 + 物理帧 + 磁盘 I/O**，代价以毫秒计。
- Cache 缺失：动的是**主存读一个块**，代价以纳秒计。

这就是为什么「缺页」通常是操作系统问题，「Cache 缺失」是体系结构问题。
