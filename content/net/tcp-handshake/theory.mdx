# TCP 连接建立与释放

## 三次握手

```
C ---- SYN seq=x ------------> S       C: SYN_SENT
C <--- SYN,ACK seq=y ack=x+1 -- S       S: SYN_RCVD
C ---- ACK seq=x+1 ack=y+1 ---> S       双方 ESTABLISHED
```

- SYN 与 FIN 各**消耗 1 个序号**，纯 ACK 不消耗。
- 为什么不是两次：只有第三次才能让服务端确认「客户端收到了我的 SYN」，
  否则一个延迟的旧 SYN 可能让服务端建立一条客户端并不认的连接。

## 四次挥手

```
主动方                          被动方
FIN  seq=u  ------------->      CLOSE_WAIT
           <-------------  ACK ack=u+1
           <-------------  FIN seq=w
ACK ack=w+1 ------------->      CLOSED
TIME_WAIT（等 2MSL）→ CLOSED
```

被动方收到 FIN 后先回 ACK、等应用层处理完才发自己的 FIN —— 这就是"四次"而不是"三次"的原因。

## 异常

| 场景 | 关键点 |
| --- | --- |
| 端口未开放 | 服务端回 RST，客户端直接 CLOSED |
| 末次 ACK 丢失 | 服务端超时**重传 FIN，序号不变**；客户端重发 ACK |
| 同时关闭 | 双方都经历 FIN_WAIT_1 → CLOSING → TIME_WAIT |
